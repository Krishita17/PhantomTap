CRITICALguessabilityCredential guessing-resistance: 0.0 bits (TRIVIAL)
A blind adversary faces ~15.0 bits of guessing to forge a valid credential; one that reasons about structure (locked facility code + bounded 500-wide range at 100.0% density) faces only ~0.0 bits. This deployment therefore **leaks ~15.0 bits** of credential security to a structure-aware attacker.
Fix: Widen the effective key space that survives inference: randomise card numbers across the full field and authenticate the credential so a guessed number alone is worthless.
CRITICALnumberingNumbering scheme: sequential
Card numbers are issued strictly sequentially. Knowing one valid card lets an assessor predict every neighbour with near certainty.
Fix: Issue card numbers from a cryptographically random, non-guessable pool and decouple them from any physical/temporal issuance order.
CRITICALkeysSector key hygiene
11/16 sectors (69%) still carry publicly documented default keys (e.g. 00000000000A, 0123456789AB, 123456789ABC). Keys are shared across the population, so recovering one card compromises all.
Fix: Rotate every sector off factory/default keys, use per-card diversified keys derived from a master + UID, and store no key material in the clear.
HIGHformatCredential format: H10301-26 (26-bit)
HID 26-bit, the ubiquitous legacy format. Tiny 8-bit facility code space (0-255) makes facility collisions and guessing trivial. The card-number field is 16 bits (max 65,535), and the facility-code field is 8 bits (max 255).
Fix: Migrate to a high-bit-count, cryptographically authenticated credential (e.g. Seos / DESFire EV2/EV3, iCLASS SE) rather than a static Wiegand format that can be read and replayed.
HIGHcharacterizationAttempts-to-characterize
Guided search characterised 90% of the issued population in 443 reader queries versus ~2,332,513 for brute force (~5,265x fewer attempts). Low attempts-to-characterize is itself a weakness signal.
Fix: Randomised numbering and authenticated credentials both raise the query cost of mapping the population.
MEDIUMclonabilityCard family: MIFARE Classic (sectored)
Sectored cards carry per-sector keys, so cloning depends on key strength. MIFARE Classic's Crypto-1 cipher is itself academically broken, so weak/default keys are decisive.
Fix: Move off MIFARE Classic/Crypto-1 to AES-authenticated DESFire-class credentials.
